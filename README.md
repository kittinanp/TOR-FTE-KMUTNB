# TOR Builder — ระบบร่างขอบเขตของงาน (TOR)

ระบบช่วยร่าง TOR งานซื้อ / งานจ้าง ตาม พ.ร.บ. การจัดซื้อจัดจ้างและการบริหารพัสดุภาครัฐ พ.ศ. 2560
รองรับการทำงาน 2 บทบาท คือ **ผู้จัดทำ (วิศวกร / ผู้กำหนดรายละเอียด)** และ **ผู้ตรวจสอบ (นักวิชาการพัสดุ)**
พร้อมร่องรอยการแก้ไข ความเห็นรายข้อ การตรวจตามระเบียบเบื้องต้น และส่งออกเป็น Word / PDF

- ตัวระบบ: ไฟล์ `index.html` ไฟล์เดียว (เปิดในเบราว์เซอร์ได้ทันที หรือวางบน GitHub Pages)
- คู่มือฉบับอินโฟกราฟิก: [`guide.html`](guide.html) (เปิดจากเมนู “คู่มือการใช้งาน” ในระบบ หรือสั่งพิมพ์เป็น PDF แจกทีม)
- ที่เก็บข้อมูล: Google Drive ผ่าน Google Apps Script (`google-apps-script/Code.gs`)
- AI ผู้ช่วย: OpenRouter / Typhoon / OpenAI / Ollama หรือบริการที่ใช้รูปแบบ OpenAI API
  ถ้ายังไม่เชื่อม Drive ระบบจะเก็บข้อมูลไว้ในเบราว์เซอร์ของแต่ละเครื่อง

---

## 1) ตั้งค่า Google Drive (ผู้ดูแลทำครั้งเดียว ~10 นาที)

ข้อมูลทั้งหมดจะอยู่ใน Google Drive ของบัญชีที่ทำขั้นตอนนี้ (แนะนำบัญชีของหน่วยงาน)

1. เข้า <https://script.google.com> → **โปรเจกต์ใหม่** → ตั้งชื่อ `TOR Builder Drive`
2. ลบโค้ดเดิมทั้งหมด แล้ววางโค้ดจากไฟล์ [`google-apps-script/Code.gs`](google-apps-script/Code.gs)
3. แก้บรรทัด `const TEAM_KEY = 'CHANGE-ME';` เป็นรหัสทีมของคุณ (เดายาก อย่างน้อย 12 ตัวอักษร) แล้วกด 💾 บันทึก
4. เลือกฟังก์ชัน **`setup`** ที่แถบด้านบน → กด **Run**
   - Google จะขอสิทธิ์เข้าถึง Drive → เลือกบัญชี
   - ถ้าขึ้น *“Google hasn’t verified this app”* ให้กด **Advanced → Go to TOR Builder Drive (unsafe)** → **Allow**
     (เป็นสคริปต์ของคุณเอง จึงยังไม่ผ่านการรับรองจาก Google — ปกติ)
   - จะมีโฟลเดอร์ **TOR Builder** เกิดขึ้นใน Drive
5. กด **Deploy → New deployment** → ไอคอนเฟือง เลือก **Web app**
   - Execute as: **Me**
   - Who has access: **Anyone**
   - กด **Deploy** แล้ว **คัดลอก Web app URL** (ลงท้ายด้วย `/exec`)

> แก้โค้ด Apps Script ภายหลัง: **Deploy → Manage deployments → ✏️ → Version: New version → Deploy** (URL เดิมใช้ต่อได้)

## 1.1) เข้าสู่ระบบด้วย ICIT Account (KMUTNB SSO) — แนะนำ

เมื่อเปิด SSO ผู้ใช้ต้องเข้าสู่ระบบด้วยบัญชี ICIT ของมหาวิทยาลัย ไม่ต้องใช้รหัสทีม และประวัติการแก้ไขจะเป็นชื่อจริงจากบัญชี

1. เข้า <https://sso.kmutnb.ac.th> ด้วย ICIT Account → เมนู **สำหรับนักพัฒนาแอป** → ลงทะเบียนแอปพลิเคชัน
   - ชื่อแอป: `TOR Builder` · หน่วยงาน: คณะครุศาสตร์อุตสาหกรรม
   - Homepage URL: `https://kittinanp.github.io/TOR-FTE-KMUTNB/`
   - Redirect URI: `https://kittinanp.github.io/TOR-FTE-KMUTNB/` (ต้องตรงทุกตัวอักษร รวม `/` ท้าย)
   - Scopes: `openid` `profile` `email` `personnel_info`
   - ประเภทบัญชีที่อนุญาต: บุคลากร (personnel)
   - สอบถามการลงทะเบียน: sso-development@icit.kmutnb.ac.th · โทร 02-555-2000 ต่อ 2229
2. ได้ **Client ID** และ **Client Secret** แล้ว ใส่ใน Apps Script → ⚙️ Project Settings → **Script Properties**

| Property | ค่า | จำเป็น |
|---|---|---|
| `SSO_CLIENT_ID` | Client ID | ✔ |
| `SSO_CLIENT_SECRET` | Client Secret (เก็บที่นี่ที่เดียว) | ✔ |
| `REVIEWERS` | username หรืออีเมลของนักวิชาการพัสดุ คั่นด้วย `,` | แนะนำ |
| `ADMINS` | ผู้ดูแลระบบ คั่นด้วย `,` | |
| `ALLOWED_USERS` | ถ้าใส่ จะให้เข้าได้เฉพาะรายชื่อนี้ | |
| `ALLOWED_ORG` | เช่น `ครุศาสตร์อุตสาหกรรม` (จำกัดเฉพาะหน่วยงาน) | |
| `ALLOWED_ACCOUNT_TYPES` | ค่าเริ่มต้น `personnel` | |

3. Deploy เวอร์ชันใหม่ (Manage deployments → New version)
4. นำ Web app URL ใส่ในไฟล์ [`config.js`](config.js) ที่ `driveUrl` แล้ว commit — ทุกคนที่เปิดเว็บจะเห็นหน้า **เข้าสู่ระบบด้วย ICIT Account** ทันที ไม่ต้องตั้งค่าเอง

สิทธิ์: บัญชีทั่วไปเป็น **ผู้จัดทำ** · รายชื่อใน `REVIEWERS` สลับเป็น **ผู้ตรวจสอบ** ได้ และเซิร์ฟเวอร์จะไม่ยอมให้บัญชีผู้จัดทำกด “ผ่านการตรวจ”
ประวัติการเข้าสู่ระบบอยู่ในไฟล์ `login-log.txt` ในโฟลเดอร์ข้อมูลระบบ

## 2) เปิดเว็บด้วย GitHub Pages

1. ไปที่ repository บน GitHub → **Settings → Pages**
2. Source: **Deploy from a branch** → Branch: **main** / **(root)** → **Save**
3. รอ 1–2 นาที จะได้ลิงก์ เช่น `https://<ชื่อบัญชี>.github.io/<ชื่อ repo>/`

## 3) เชื่อมระบบกับ Drive และชวนทีม (กรณีไม่ใช้ SSO)

1. เปิดลิงก์เว็บ → เมนู **ตั้งค่าหน่วยงาน**
2. ส่วน **เก็บข้อมูลใน Google Drive** → วาง *Web app URL* และ *รหัสทีม* → **เชื่อมต่อ**
3. กด **คัดลอกลิงก์เชิญทีม** แล้วส่งให้วิศวกรและนักวิชาการพัสดุ (ทางไลน์/อีเมลส่วนตัว)
   คนที่เปิดลิงก์จะเชื่อม Drive ให้อัตโนมัติ แล้วตั้งชื่อตัวเองในหน้าตั้งค่า

## 4) เปิดใช้ AI ผู้ช่วย (ไม่บังคับ)

AI ช่วยได้ 3 อย่าง: **ร่างสเปกจากคำอธิบาย** · **ปรับภาษารายข้อ** (เห็นเทียบก่อนยอมรับ) · **ตรวจตามระเบียบละเอียด** (สำหรับผู้ตรวจ)

**แบบแนะนำ — key เก็บที่ Google (ผู้ใช้ในทีมไม่เห็น key)**
1. สมัครและสร้าง API key ที่ <https://openrouter.ai/keys> (หรือ Typhoon / OpenAI)
2. Apps Script → ⚙️ **Project Settings → Script Properties** → เพิ่ม
   - `AI_KEY` = API key
   - `AI_BASE` = (ไม่ใส่ = OpenRouter) เช่น `https://api.opentyphoon.ai/v1`
   - `AI_MODEL` = โมเดลเริ่มต้น (ไม่บังคับ)
3. ถ้า Deploy ไว้ก่อนแก้ `Code.gs` เวอร์ชันนี้ ให้ Deploy เวอร์ชันใหม่ (Manage deployments → New version)
4. ในระบบ: ตั้งค่า → **AI ผู้ช่วย** → วิธีเชื่อมต่อ “ผ่าน Apps Script ของทีม” → **โหลดรายชื่อ** → เลือกโมเดล → **ทดสอบ AI**
   (การเลือกโมเดลเก็บแยกต่อเครื่อง)

**แบบใช้ key ของตัวเอง** — เลือก “ใช้ API key ของฉัน” แล้วกรอก key (เก็บในเบราว์เซอร์นั้นเท่านั้น)
Ollama ในเครื่องต้องตั้ง `OLLAMA_ORIGINS` ให้อนุญาตโดเมนของเว็บ

> AI อาจผิดพลาด — ทุกการแก้จาก AI แสดงเป็นร่องรอยการแก้ไขและบันทึกในประวัติ ผู้ตรวจสอบต้องพิจารณาเองทุกครั้ง
> ค่าใช้จ่าย AI คิดตามการใช้งานจริงกับผู้ให้บริการที่เลือก

## โครงสร้างใน Google Drive

```
TOR Builder/
├── ข้อมูลระบบ (ห้ามแก้ไขไฟล์ในนี้)/   ← ร่าง TOR แต่ละฉบับ (.json) ความเห็น ประวัติ
└── เอกสาร Word/                       ← ไฟล์ .docx ที่กด “Word” จากระบบ (บันทึกให้อัตโนมัติ)
```

ไฟล์ที่ลบจากระบบจะย้ายไป **ถังขยะของ Drive** (กู้คืนได้ภายใน 30 วัน)

## การทำงานร่วมกัน

| ขั้นตอน | ใครทำ | ในระบบ |
|---|---|---|
| ร่าง | ผู้จัดทำ | เลือกแม่แบบ กรอกรายละเอียด → **ส่งให้ผู้ตรวจ** |
| ตรวจ | ผู้ตรวจสอบ | คลิกแก้คำบนเอกสาร / เพิ่ม-ลบข้อ / แนบความเห็น → **ส่งกลับแก้ไข** หรือ **ผ่านการตรวจ** |
| แก้ตามความเห็น | ผู้จัดทำ | แผง **ตรวจทาน** → ยอมรับ / ย้อนกลับการแก้ไขทีละจุด |
| ส่งออก | ทุกคน | **Word** (บันทึกลง Drive ด้วย) หรือ **พิมพ์ / PDF** — ได้ฉบับสะอาดไม่มีร่องรอย |

ถ้าสองคนแก้ฉบับเดียวกันพร้อมกัน ระบบจะถามว่าจะโหลดฉบับใน Drive, บันทึกทับ หรือเก็บของตัวเองเป็นสำเนา — ข้อมูลไม่หายเงียบ ๆ

## ความปลอดภัย (โปรดอ่าน)

- โค้ดบน GitHub **ไม่มี** รหัสลับใด ๆ — Client Secret, รหัสทีม และ AI key อยู่ใน Script Properties ของ Apps Script เท่านั้น (Web app URL ใน `config.js` ไม่ใช่ความลับ เพราะเรียกใช้ได้ต่อเมื่อเข้าสู่ระบบแล้ว)
- เมื่อเปิด SSO: เซสชันมีอายุ 12 ชั่วโมง ลงลายมือชื่อดิจิทัล (HMAC) ฝั่งเซิร์ฟเวอร์ ปลอมชื่อผู้แก้ไขไม่ได้
- ใครที่มีทั้ง *Web app URL* และ *รหัสทีม* จะอ่าน/แก้ข้อมูลได้ → ส่งลิงก์เชิญเฉพาะคนในทีม
  ถ้ารหัสหลุด ให้เปลี่ยน `TEAM_KEY` ใน Apps Script แล้ว Deploy เวอร์ชันใหม่ จากนั้นส่งลิงก์เชิญใหม่
- ถ้าไม่เปิด SSO (ใช้รหัสทีม) ชื่อผู้แก้ไขมาจากชื่อที่ผู้ใช้ตั้งเอง — เหมาะกับการทดลองใช้ภายในทีมเท่านั้น
- อย่านำเอกสาร TOR จริงที่มีลายมือชื่อขึ้น repository (ไฟล์ `.gitignore` กันโฟลเดอร์ `ตัวอย่าง/` และไฟล์ PDF/Word ไว้แล้ว)
