# TOR Builder — ระบบร่างขอบเขตของงาน (TOR)

ระบบช่วยร่าง TOR งานซื้อ / งานจ้าง ตาม พ.ร.บ. การจัดซื้อจัดจ้างและการบริหารพัสดุภาครัฐ พ.ศ. 2560
รองรับการทำงาน 2 บทบาท คือ **ผู้จัดทำ (วิศวกร / ผู้กำหนดรายละเอียด)** และ **ผู้ตรวจสอบ (นักวิชาการพัสดุ)**
พร้อมร่องรอยการแก้ไข ความเห็นรายข้อ การตรวจตามระเบียบเบื้องต้น และส่งออกเป็น Word / PDF

- ตัวระบบ: ไฟล์ `index.html` ไฟล์เดียว (เปิดในเบราว์เซอร์ได้ทันที หรือวางบน GitHub Pages)
- ที่เก็บข้อมูล: Google Drive ผ่าน Google Apps Script (`google-apps-script/Code.gs`)
  ถ้ายังไม่เชื่อม Drive ระบบจะเก็บข้อมูลไว้ในเบราว์เซอร์ของแต่ละเครื่อง

---

## 1) ตั้งค่า Google Drive (ผู้ดูแลทำครั้งเดียว ~10 นาที)

ข้อมูลทั้งหมดจะอยู่ใน Google Drive ของบัญชีที่ทำขั้นตอนนี้ (แนะนำบัญชีของหน่วยงาน)

1. เข้า <https://script.google.com> → **โปรเจกต์ใหม่** → ตั้งชื่อ `TOR Builder Drive`
2. ลบโค้ดเดิมทั้งหมด แล้ววางโค้ดจากไฟล์ [`google-apps-script/Code.gs`](google-apps-script/Code.gs)
3. แก้บรรทัด `const TEAM_KEY = 'CHANGE-ME';` เป็นรหัสทีมของคุณ (เดายาก อย่างน้อย 12 ตัวอักษร) แล้วกด 💾 บันทึก
4. เลือกฟังก์ชัน **`setup`** ที่แถบด้านบน → กด **Run**
   - Google จะขอสิทธิ์เข้าถึง Drive → เลือกบัญชี
   - ถ้าขึ้น *“Google hasn’t verified this app”* ให้กด **Advanced → Go to TOR Builder Drive (unsafe)** → **Allow**
     (เป็นสคริปต์ของคุณเอง จึงยังไม่ผ่านการรับรองจาก Google — ปกติ)
   - จะมีโฟลเดอร์ **TOR Builder** เกิดขึ้นใน Drive
5. กด **Deploy → New deployment** → ไอคอนเฟือง เลือก **Web app**
   - Execute as: **Me**
   - Who has access: **Anyone**
   - กด **Deploy** แล้ว **คัดลอก Web app URL** (ลงท้ายด้วย `/exec`)

> แก้โค้ด Apps Script ภายหลัง: **Deploy → Manage deployments → ✏️ → Version: New version → Deploy** (URL เดิมใช้ต่อได้)

## 2) เปิดเว็บด้วย GitHub Pages

1. ไปที่ repository บน GitHub → **Settings → Pages**
2. Source: **Deploy from a branch** → Branch: **main** / **(root)** → **Save**
3. รอ 1–2 นาที จะได้ลิงก์ เช่น `https://<ชื่อบัญชี>.github.io/<ชื่อ repo>/`

## 3) เชื่อมระบบกับ Drive และชวนทีม

1. เปิดลิงก์เว็บ → เมนู **ตั้งค่าหน่วยงาน**
2. ส่วน **เก็บข้อมูลใน Google Drive** → วาง *Web app URL* และ *รหัสทีม* → **เชื่อมต่อ**
3. กด **คัดลอกลิงก์เชิญทีม** แล้วส่งให้วิศวกรและนักวิชาการพัสดุ (ทางไลน์/อีเมลส่วนตัว)
   คนที่เปิดลิงก์จะเชื่อม Drive ให้อัตโนมัติ แล้วตั้งชื่อตัวเองในหน้าตั้งค่า

## โครงสร้างใน Google Drive

```
TOR Builder/
├── ข้อมูลระบบ (ห้ามแก้ไขไฟล์ในนี้)/   ← ร่าง TOR แต่ละฉบับ (.json) ความเห็น ประวัติ
└── เอกสาร Word/                       ← ไฟล์ .docx ที่กด “Word” จากระบบ (บันทึกให้อัตโนมัติ)
```

ไฟล์ที่ลบจากระบบจะย้ายไป **ถังขยะของ Drive** (กู้คืนได้ภายใน 30 วัน)

## การทำงานร่วมกัน

| ขั้นตอน | ใครทำ | ในระบบ |
|---|---|---|
| ร่าง | ผู้จัดทำ | เลือกแม่แบบ กรอกรายละเอียด → **ส่งให้ผู้ตรวจ** |
| ตรวจ | ผู้ตรวจสอบ | คลิกแก้คำบนเอกสาร / เพิ่ม-ลบข้อ / แนบความเห็น → **ส่งกลับแก้ไข** หรือ **ผ่านการตรวจ** |
| แก้ตามความเห็น | ผู้จัดทำ | แผง **ตรวจทาน** → ยอมรับ / ย้อนกลับการแก้ไขทีละจุด |
| ส่งออก | ทุกคน | **Word** (บันทึกลง Drive ด้วย) หรือ **พิมพ์ / PDF** — ได้ฉบับสะอาดไม่มีร่องรอย |

ถ้าสองคนแก้ฉบับเดียวกันพร้อมกัน ระบบจะถามว่าจะโหลดฉบับใน Drive, บันทึกทับ หรือเก็บของตัวเองเป็นสำเนา — ข้อมูลไม่หายเงียบ ๆ

## ความปลอดภัย (โปรดอ่าน)

- โค้ดบน GitHub **ไม่มี** URL หรือรหัสทีม — ผู้ใช้กรอกเองในเบราว์เซอร์
- ใครที่มีทั้ง *Web app URL* และ *รหัสทีม* จะอ่าน/แก้ข้อมูลได้ → ส่งลิงก์เชิญเฉพาะคนในทีม
  ถ้ารหัสหลุด ให้เปลี่ยน `TEAM_KEY` ใน Apps Script แล้ว Deploy เวอร์ชันใหม่ จากนั้นส่งลิงก์เชิญใหม่
- ชื่อผู้แก้ไขในประวัติมาจากชื่อที่ผู้ใช้ตั้งเอง (ไม่ใช่การยืนยันตัวตนด้วยบัญชี Google)
  เหมาะกับการทดลองใช้ภายในทีม — การใช้งานจริงระดับมหาวิทยาลัยควรเชื่อมระบบล็อกอิน / ERP ของมหาวิทยาลัย
- อย่านำเอกสาร TOR จริงที่มีลายมือชื่อขึ้น repository (ไฟล์ `.gitignore` กันโฟลเดอร์ `ตัวอย่าง/` และไฟล์ PDF/Word ไว้แล้ว)

## การตรวจตามระเบียบอัตโนมัติ

เป็นตัวช่วยเบื้องต้นเท่านั้น เช่น จับคำที่อาจระบุยี่ห้อ/รุ่น (มาตรา 9), ค่าตัวเลขตายตัวที่ไม่มี “ไม่น้อยกว่า / หรือดีกว่า”,
ช่อง `...` ที่ยังไม่เติม, เงื่อนไขส่งมอบ/ยืนราคา/รับประกันที่ขาด — ผู้ตรวจสอบควรพิจารณาประกอบระเบียบทุกครั้ง
